# Использование локальных LLM через Ollama

Этот проект поддерживает работу с локальными LLM-моделями через **Ollama**.

## Требования

1. **Установите Ollama**: https://ollama.ai
2. **Загрузите модель**:
   ```bash
   ollama pull gemma3:1b
   ollama pull gemma3:270m
   ```

## Настройка

### Вариант 1: Через `.env` файл

Скопируйте `.env.example` в `.env` и настройте:

```env
# Выбор провайдера: 'ollama' для локальных моделей
LLM_PROVIDER=ollama

# Имя модели (без префикса 'ollama/')
LLM_MODEL_NAME=gemma3:1b

# Адрес Ollama API (по умолчанию http://localhost:11434)
LLM_API_BASE=http://localhost:11434

# Таймаут запросов в секундах (опционально, полезно для медленных моделей)
LLM_TIMEOUT=120
```

### Вариант 2: Через переменные окружения

```bash
set LLM_PROVIDER=ollama
set LLM_MODEL_NAME=gemma3:1b
set LLM_API_BASE=http://localhost:11434
```

## Запуск игры

1. **Убедитесь, что Ollama запущен**:
   - На Windows: запустите приложение Ollama из меню Пуск
   - Или в терминале: `ollama serve`

2. **Проверьте, что модель загружена**:
   ```bash
   ollama list
   ```
   Если модели нет в списке, загрузите её:
   ```bash
   ollama pull gemma3:1b
   ```

3. **Запустите игру**:
   ```bash
   python main.py
   ```

   > **Примечание**: При запуске игра автоматически загрузит модель в память Ollama. Это может занять 10-60 секунд в зависимости от вашего оборудования. После загрузки модель остаётся в памяти и последующие запросы будут быстрыми.

## Доступные модели

Проект протестирован с моделями:
- `gemma3:1b` — быстрая модель для тестирования
- `gemma3:270m` — очень быстрая, но менее точная

Вы можете использовать любые другие модели из каталога Ollama:
- `llama3.2`
- `mistral`
- `phi3`
- и другие

## Архитектурные детали

Проект использует **паттерн Adapter** для интеграции LLM:

- `ILLMService` — интерфейс (порт) в `application/ports/llm_service.py`
- `LitellmService` — адаптер для облачных API (OpenAI, Anthropic, Azure)
- `OllamaLLMService` — адаптер для локальных моделей Ollama

> **Важно:** `OllamaLLMService` использует **subprocess + curl** для вызова Ollama API, а не Python-библиотеку `ollama`. Это сделано для обхода проблем с совместимостью Python 3.13 на Windows.

Выбор провайдера происходит в `container.py` на основе настройки `LLM_PROVIDER`.

## Troubleshooting

### Ошибка: "Cannot connect to Ollama"

Убедитесь, что Ollama запущен:
- На Windows: запустите приложение Ollama из меню Пуск
- В терминале: `ollama serve`

### Ошибка: "Model not found"

Загрузите модель:
```bash
ollama pull gemma3:1b
```

### Ошибка: "503 Service Unavailable"

Модель не загружена в память. Игра автоматически пытается загрузить модель при запуске.

Если ошибка возникает во время игры:
1. Дождитесь завершения загрузки (может занять до 60 секунд)
2. Или предварительно загрузите модель в отдельном терминале:
   ```bash
   ollama run gemma3:1b
   ```
3. Убедитесь, что на вашей видеокарте достаточно VRAM для модели

### Медленная генерация

- Используйте более легкую модель (`gemma3:270m`)
- Увеличьте таймаут: `LLM_TIMEOUT=120`
- Убедитесь, что у вас достаточно RAM/VRAM

### Ошибка: "No module named 'ollama'"

Библиотека `ollama` не требуется для работы. Проект использует `curl` через subprocess для вызова API Ollama.

Убедитесь, что:
1. `curl` доступен в вашей системе (обычно предустановлен)
2. Ollama запущен и доступен по адресу `http://localhost:11434`
