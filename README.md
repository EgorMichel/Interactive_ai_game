# UIN Engine: Interactive AI Game

UIN Engine — это фреймворк с открытым исходным кодом для создания интерактивных сюжетных игр, основанных на искусственном интеллекте. Движок использует большие языковые модели (LLM) для генерации динамичных и непредсказуемых диалогов с NPC, что позволяет создавать уникальный игровой опыт при каждом прохождении.

В качестве демонстрации поставляется сценарий **"The Nereid Yacht Mystery"** — детективная история об убийстве на роскошной яхте.

## 🚀 Основная концепция

Сердце движка — это симуляция живого мира, в котором неигровые персонажи (NPC) обладают собственными знаниями, целями и расписанием. В отличие от традиционных игр с заранее прописанными диалогами, UIN Engine использует LLM для генерации ответов NPC в реальном времени, основываясь на их личности, известных им фактах и контексте разговора. Это открывает безграничные возможности для нелинейного повествования.

## ✨ Функциональность

### Реализовано (v0.20)
*   **Многоуровневая система памяти:** Персонажи обладают комплексной памятью, включающей ядро личности (роль, цели), семантические знания (факты) и эпизодическую память (личный лог событий), которая со временем сжимается для имитации забывания и обеспечения долгосрочного контекста.
*   **Динамические диалоги и извлечение фактов:** Общайтесь с NPC на свободные темы. LLM не только генерирует ответы, но и может распознавать и извлекать из диалога ключевые факты, пополняя базу знаний персонажей.
*   **Исследование мира:** Перемещайтесь между локациями, осматривайтесь и находите улики.
*   **Интерактивные объекты:** Исследуйте предметы в локациях, чтобы обнаружить новые факты и продвинуться по сюжету.
*   **Симуляция жизни NPC:** У персонажей есть базовое расписание, которому они следуют, перемещаясь по локациям независимо от игрока.
*   **Гибкая система сценариев:** Все игровые миры, персонажи и сюжеты загружаются из простых для редактирования YAML-файлов.
*   **Консольный интерфейс:** Удобный CLI для полного погружения в текстовое приключение.
*   **Поддержка локальных моделей:** Работа с Ollama для запуска LLM локально (без облачных API).

### Планируется
*   **Персистентность:** Сохранение состояния игры между сессиями (SQLite).
*   **Продвинутое поведение NPC:** Реакция NPC на события в мире (обнаружение улик, действия игрока) и взаимодействие друг с другом.
*   **Система инвентаря:** Возможность подбирать, хранить и использовать предметы.
*   **Веб-интерфейс:** Создание красивого и удобного UI для игры в браузере.
*   **Редактор сценариев:** Графический инструмент для упрощения создания собственных историй.

## 🏗️ Архитектура

Проект построен на принципах **Чистой архитектуры** (Clean Architecture), что делает его невероятно гибким, тестируемым и расширяемым.

```
┌───────────────────┐
│     Interface     │  (CLI, будущее Web API)
└─────────┬─────────┘
          │
┌─────────▼─────────┐
│    Application    │  (Use Cases, Ports)
└─────────┬─────────┘
          │
┌─────────▼─────────┐
│       Domain      │  (Бизнес-логика, Сущности)
└─────────┬─────────┘
          │
┌─────────▼─────────┐
│  Infrastructure   │  (БД, LLM-сервисы, Шина событий)
└───────────────────┘
```

*   **Domain:** Ядро, содержащее чистую бизнес-логику и сущности (`GameWorld`, `Character`, `Location`). Не зависит ни от каких внешних библиотек.
*   **Application:** Оркестрирует доменные сущности для выполнения сценариев использования (`TalkToCharacter`, `MoveCharacter`). Определяет "порты" (интерфейсы) для внешних сервисов.
*   **Infrastructure:** Реализует "порты" из прикладного слоя. Здесь происходит реальная работа с базами данных, LLM и другими внешними сервисами.
*   **Interface:** Точка входа для пользователя (на данный момент — консольный интерфейс).

**Преимущества такого подхода:**
- **Расширяемость:** Хотите сменить OpenAI на локальную модель? Просто напишите новый адаптер в слое `Infrastructure`, и остальной код не потребует изменений.
- **Тестируемость:** Каждый слой можно тестировать независимо, подменяя зависимости на "моки" и "стабы".
- **Поддерживаемость:** Четкое разделение ответственности делает код понятным и легким для модификации.

## ⚙️ Как начать

### Требования
*   Python 3.10+

### Установка и запуск
1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/your-username/Interactive_ai_game.git
    cd Interactive_ai_game
    ```

2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    # Для Windows
    python -m venv .venv
    .\.venv\Scripts\activate
    
    # Для macOS/Linux
    python3 -m venv .venv
    source .venv/bin/activate
    ```

3.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

4.  **Настройте API LLM:**
    - Скопируйте файл `.env.example` в `.env`.
    - Откройте файл `.env` и **внимательно** заполните его:

      **Вариант A: Облачные API (OpenAI, Anthropic, Azure через LiteLLM)**
      ```
      # Выбор провайдера: 'litellm' для облачных API
      LLM_PROVIDER=litellm

      # Ваш ключ доступа к API
      LLM_API_KEY="sk-..."

      # URL эндпоинта (для OpenAI можно не указывать)
      LLM_API_BASE="https://api.openai.com/v1"

      # Название модели (для LiteLLM используйте префикс провайдера)
      LLM_MODEL_NAME="openai/gpt-3.5-turbo"
      ```

      **Вариант B: Локальные модели через Ollama**
      ```
      # Выбор провайдера: 'ollama' для локальных моделей
      LLM_PROVIDER=ollama

      # Адрес Ollama API (по умолчанию)
      LLM_API_BASE=http://localhost:11434

      # Название локальной модели (без префикса 'ollama/')
      LLM_MODEL_NAME="gemma3:1b"
      ```
      > **Важно:** Для использования Ollama убедитесь, что он установлен и запущен. См. [docs/ollama_setup.md](docs/ollama_setup.md) для деталей.

5.  **Запустите игру:**
    - Убедитесь, что ваше виртуальное окружение активировано.
    - Для Windows:
        ```bash
        python main.py
        ```
    - Для macOS/Linux:
        ```bash
        python main.py
        ```
    *(Если команда `python` не работает, попробуйте `python3`)*

    **Запуск собственного сценария:**
    ```bash
    python main.py --scenario scenarios/my_scenario.yaml
    ```

6.  **Просмотр логов (опционально):**
    - После запуска в корневой директории проекта будет создан файл `game.log`.
    - В нем содержится детальная информация обо всех игровых событиях, а также полные промпты, отправляемые языковой модели (на уровне `DEBUG`), что очень полезно для отладки.

### Игровые команды
*   `look` — осмотреть текущую локацию, увидеть выходы, объекты и персонажей.
*   `move <название локации>` — перейти в другую локацию.
*   `talk <имя персонажа> [сообщение]` — начать диалог с персонажем (можно сразу с первым сообщением).
*   `[любой текст]` — если вы уже начали диалог, просто вводите текст для продолжения.
*   `goodbye` — закончить текущий диалог и вернуться в режим исследования.
*   `examine <название объекта>` — исследовать объект в текущей локации.
*   `accuse <имя персонажа>` — обвинить персонажа в совершении преступления.
*   `quit` — выйти из игры.

## 📝 Создание собственного сценария

Вы можете легко создать свой собственный мир, скопировав и изменив `scenarios/yacht_mystery.yaml`. Структура файла интуитивно понятна.

### Структура YAML-файла сценария

*   `id` и `name`: Уникальный идентификатор и название вашего сценария.
*   `start_location`: ID локации, где начинается игра.
*   `player_id`: ID персонажа, которым управляет игрок.
*   `facts`: Список всех фактов, которые могут быть известны в игре.
    - `id`: Уникальный ID факта.
    - `content`: Текстовое описание факта.
*   `locations`: Список всех локаций в игре.
    - `id`, `name`, `description`: Основная информация о локации.
    - `connections`: Список ID других локаций, в которые можно перейти из текущей.
    - `objects`: Список объектов внутри локации.
        - `clues`: Список улик, которые можно найти на объекте. Каждая улика связана с `fact_id`.
*   `characters`: Список всех персонажей.
    - `id`, `name`, `description`: Основная информация о персонаже.
    - `initial_location`: ID локации, где персонаж находится в начале игры.
    - `goals`: Список целей, которые влияют на поведение персонажа (используется в промпте для LLM).
    - `initial_knowledge`: Словарь фактов, известных персонажу в начале игры (ID факта и степень уверенности от 0.0 до 1.0).
    - `schedule`: Расписание действий NPC.
        - `time`: Игровое время (ЧЧ:ММ).
        - `action_type`: Тип действия (`move`, `idle`).
        - `target`: Цель действия (например, ID локации для `move`).

Чтобы запустить свой сценарий, передайте путь к файлу при запуске:
```bash
python main.py --scenario scenarios/my_scenario.yaml
```

## 💻 Стек технологий

*   **Язык:** Python 3.10+
*   **Асинхронность:** `asyncio`
*   **Валидация данных:** `Pydantic`, `pydantic-settings`
*   **Интеграция с LLM:** `LiteLLM` (OpenAI, Anthropic, Azure) + `ollama` (локальные модели через subprocess)
*   **Внедрение зависимостей (DI):** `dependency-injector`
*   **Конфигурация:** `PyYAML`
*   **Тестирование:** `pytest`, `pytest-asyncio`

## ⚠️ Ограничения текущей версии (MVP)

*   **Нет персистентности:** Состояние игры не сохраняется между сессиями (только in-memory хранение).
*   **Только CLI:** Веб-интерфейс и API пока не реализованы.
*   **Один активный игрок:** Мультиплеер не поддерживается.
